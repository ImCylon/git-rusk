# Configuration

git-rusk is configured through a TOML file (`.git-rusk.toml`) plus a small set of environment variables used at hook-execution time. This document covers every configurable knob, its default, and whether it is required.

A JSON Schema describing the config file lives at [`schema.json`](../schema.json) in the repository root — editors with TOML/JSON-schema support can use it for validation and autocompletion.

## Configuration Sources

Configuration is resolved in the following order (later sources win):

1. **Built-in defaults** — every field has a default; an empty or partial config file is valid.
2. **`.git-rusk.toml`** in the current working directory — auto-discovered when `--config` is not passed.
3. **`--config <FILE>`** global CLI flag — explicitly points at a config file anywhere on disk. If the file does not exist or fails to parse, git-rusk exits with an error.
4. **`--default-branch <NAME>`** global CLI flag — overrides `branches.default_branch` and takes precedence over the TOML value.

Resolution is implemented in `src/config.rs` (`Config::load`) and `src/lib.rs` (`resolve_config`). Partial configs are supported: every section and sub-struct is annotated with `#[serde(default)]`, so omitting a key keeps its built-in default.

## Environment Variables

git-rusk reads a small number of environment variables. None are required for basic usage (commits without TOTP), but several become required the moment TOTP verification is enabled.

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `TOTP_CODE` | Conditional | _(none)_ | The 6-digit TOTP code to verify. **Required** whenever a hook triggers TOTP verification (see `[totp]` toggles below). If unset when needed, the hook fails with `TOTP_CODE environment variable is not set`. |
| `XDG_CONFIG_HOME` | Optional | _(none)_ | Base directory for the global TOTP secret. When set, the secret is read from `$XDG_CONFIG_HOME/git-rusk/totp-secret`. |
| `HOME` | Optional | _(none)_ | Fallback for the TOTP secret location when `XDG_CONFIG_HOME` is unset. The secret is then read from `$HOME/.config/git-rusk/totp-secret`. |
| `PATH` | Optional | _(system)_ | Must contain the `git` executable. git-rusk shells out to the system `git` binary for all repository operations. |

Example — committing to a protected branch with TOTP enabled:

```bash
TOTP_CODE=123456 git commit -m "fix(auth): correct token expiry check

The previous calculation used the wrong time window."
```

## Config File Format

- **Location:** `.git-rusk.toml` in the repository root (auto-discovered), or any path passed to `--config`.
- **Format:** TOML 1.0, parsed with the `toml` crate and `serde::Deserialize`.
- **Generated by `init`:** Running `git-rusk init` writes a fully-populated `.git-rusk.toml` (serialized via `toml::to_string_pretty`) into the target repository, unless one already exists.
- **Top-level tables:** `[branches]`, `[commit]`, `[totp]`. All three are optional and merge with defaults.

A complete minimal config (every omitted field keeps its default):

```toml
[branches]
allowed = ["development"]
protected = ["main", "release"]
default_branch = "development"

[commit]
types = ["feat", "fix", "docs", "refactor", "chore", "test", "style"]
scopes = "all"
min_body_length = 10

[totp]
require_for_commit = false
require_for_branch_switch = false
step_seconds = 30
backward_tolerance_secs = 120
```

### `[branches]`

Controls which branches are treated as open vs. protected, and where the post-commit hook returns you after committing on a protected branch.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `allowed` | array of strings | `["development"]` | Branches that **do not** require TOTP and do not trigger auto-return. Supports exact names and `prefix/*` wildcards (single path level only). |
| `protected` | array of strings | `["main", "release"]` | Branches considered protected. Presence here drives auto-return behavior; TOTP gating is controlled by the `[totp]` toggles. |
| `default_branch` | string | `"development"` | Branch the post-commit hook checks out after a commit lands on a protected (non-allowed) branch. Overridable via `--default-branch`. |

Wildcard matching is implemented in `src/branch_protection.rs`: `hotfix/*` matches `hotfix/123` but **not** `hotfix/subdir/123` or `hotfix-subdir/123`.

### `[commit]`

Conventional Commit validation rules, enforced by the `commit-msg` hook.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `types` | `"all"` **or** array of strings | `["feat", "fix", "docs", "refactor", "chore", "test", "style"]` | Allowed commit types (the segment before the optional scope). The literal string `"all"` disables type checking. Any other bare string is rejected. |
| `scopes` | `"all"` **or** array of strings | `"all"` | Allowed scopes (the segment in parentheses). The literal string `"all"` disables scope checking. An empty array `[]` rejects every scope. |
| `min_body_length` | integer | `10` | Minimum number of characters in the commit body (excluding the header and footers). |

The `types`/`scopes` fields use a custom serde format (`AllowList` in `src/config.rs`): the value is either the string `"all"` or a TOML array of strings — nothing else. Round-trips losslessly.

### `[totp]`

TOTP verification behavior. TOTP is **off by default**; flipping either toggle below requires a global TOTP secret (see [TOTP Secret](#totp-secret)) and `TOTP_CODE` to be present in the environment at commit/checkout time.

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `require_for_commit` | boolean | `false` | When `true`, the pre-commit hook verifies `TOTP_CODE` for commits on an allowed branch. Commits on non-allowed (protected) branches are always blocked with `CommitBlockedOnProtectedBranch` regardless of this setting; TOTP never enables committing to a protected branch. |
| `require_for_branch_switch` | boolean | `false` | When `true`, the post-checkout hook verifies `TOTP_CODE` after switching onto a protected branch. |
| `step_seconds` | integer | `30` | TOTP time step in seconds. Per `schema.json`: minimum 15, maximum 300. Standard authenticator apps use 30. |
| `backward_tolerance_secs` | integer | `120` | Backward time-skew tolerance in seconds. Per `schema.json`: minimum 0, maximum 900. Internally converted to totp-rs symmetric skew via `backward_tolerance_secs / step_seconds`. |

The verifier uses SHA-1, 6 digits, RFC 6238 (`src/totp.rs::build_totp`). With the defaults (`120 / 30`), a code remains valid for **4 steps backward and forward** from the current step.

## Required vs. Optional Settings

**No config key is required at the file level.** An empty `.git-rusk.toml` (or no file at all) yields a working configuration using built-in defaults. Settings only become required conditionally:

| Setting | When it becomes required | Failure mode |
|---------|--------------------------|--------------|
| `--config <FILE>` (if passed) | Always, once the flag is given | `Failed to read config file …` / `Failed to parse config file …` and exit code 1 |
| Global TOTP secret file | When `require_for_commit` or `require_for_branch_switch` is `true` and a matching hook fires | `TOTP secret not found at <path>. Run 'git-rusk totp init' to create one.` |
| `TOTP_CODE` env var | Same conditions as above | `TOTP_CODE environment variable is not set` |
| `PATH` contains `git` | Every git-rusk invocation that touches a repository | `Git is not installed or not on PATH` |
| TOTP secret file mode `0600` | Whenever the secret is read | `TOTP secret file <path> has insecure permissions: <mode> (expected 600)` |

Type/format validation (e.g. `types = "maybe"`, a non-integer `step_seconds`) produces a `Failed to parse config file` error at load time and prevents the command from running.

## TOTP Secret

The global TOTP secret is stored **outside** the repository so it is never accidentally committed. Its location is resolved in `src/totp.rs::secret_file_path`:

```
$XDG_CONFIG_HOME/git-rusk/totp-secret
  └─ fallback → $HOME/.config/git-rusk/totp-secret
```

- **Created by** `git-rusk totp init` (generates a 160-bit CSPRNG secret) or `git-rusk totp init --secret <BASE32>` / `git-rusk totp reset --secret <BASE32>` (user-supplied).
- **Permissions:** the file is written with mode `0600`. On read, git-rusk refuses to load any secret whose mode is not exactly `0600`.
- **Content:** a single Base32-encoded string (whitespace is trimmed on read).
- **Displayed by** `git-rusk totp show`, which prints both the Base32 secret and an `otpauth://` URI suitable for QR-code generation in standard authenticator apps (Google Authenticator, Authy, etc.).
- **Rotated by** `git-rusk totp reset` (use `--force` to skip confirmation, `--secret` to supply a new value).

## Per-Environment Overrides

git-rusk does **not** ship per-environment config files (there is no `.env.development`, `.env.production`, `.env.test`, or `NODE_ENV`-style switching). Configuration differences between machines are handled by one of these mechanisms:

- **Per-repository `.git-rusk.toml`** — each repository carries its own config; different projects can have different rules.
- **`--config <FILE>`** — point at an environment-specific file (e.g. a CI-only config checked in elsewhere) without modifying the repository's file.
- **`--default-branch <NAME>`** — quick per-invocation override of the auto-return target.
- **`XDG_CONFIG_HOME` / `HOME`** — isolating the TOTP secret to a specific directory per host (useful on shared servers where multiple users share a machine but need distinct secrets).
